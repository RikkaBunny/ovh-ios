# Android 数据安全核对

依赖审计日期：2026-10-03。iOS 与 Android 扫码实现不同，不能直接将 iOS 的“未收集数据”答复复制到 Google Play。

本版本 `mobile_scanner 7.4.2` 的 Android 实现依赖 Google ML Kit 条码扫描。二维码图片与结果在设备上处理；Google 的 [官方数据披露](https://developers.google.com/ml-kit/android-data-disclosure) 指出 SDK 收集设备/应用信息、安装标识符、性能、配置、事件与错误数据用于诊断和使用分析，使用 HTTPS 传输。这里不将“开发者没有集中数据收集后端”等同于“第三方 SDK 不收集数据”。

Google Play 表单须结合其当前选项核对：

| 类别 | 本版本事实 |
|---|---|
| 设备或其他标识符 | ML Kit bundled barcode SDK 使用安装标识符，供 Google 诊断/分析 |
| 诊断、其他性能数据 | 设备及应用版本、扫描配置、延迟和错误信息等 |
| 应用活动 / 应用互动 | SDK 功能初始化、检测、资源释放等事件；依据当前表单和 Google 的分类说明确认 |
| 处理目的 | 诊断、分析；没有广告 SDK、广告个性化或广告标识符读取 |
| 传输保护 | 面板与 SDK 请求均使用 HTTPS |
| 图片与扫码内容 | QR 图片和解码结果本机处理，不上传开发者采集服务 |
| 面板数据 | 用户选择的自建服务器处理令牌、账户、设备名称、实例及操作；按该服务器运营者的政策处理 |
| 设备存储 | flutter_secure_storage；本机偏好设置；系统备份关闭 |
| 删除 | 断开清除本机令牌，网页撤销服务器设备授权；SDK 数据按 Google 政策处理，不能声称断开会删除 Google SDK 数据 |

这份文档是申报准备材料，没有代替未完成的商店表单、法律确认或审核结果。商店注册与数据安全提交需要实际开发者账号。公开隐私政策已包含 Android SDK 信息。
